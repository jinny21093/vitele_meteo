# stage-s — ночной заморозочный дежурный (frost duty) v1.1.0

Автономная оценка глубины ночного заморозка на даче по связке
«собственная метеостанция + Open-Meteo», с алертами Telegram и Kuma.

## Состав

- `frost_calc.py` — stdlib-only скрипт, режимы:
  - `--evening` (21:30 МСК) — первичная оценка предстоящей ночи
  - `--midnight` (00:10 МСК) — контроль по расхождению факт-vs-модель,
    правило сценария (≤ −0.5° → холодный, гейт по облачности ≤ 50%)
  - `--verify` (09:30 МСК) — факт прошедшей ночи → `frost_log.csv`
    (обучение калибровки), сезонные счётчики, Kuma обратно в green
  - `--set K=V` — ручной оверрайд сезонного контура:
    `season=garden|winter` (сбрасывает счётчики), `digest=on|off`,
    `frost_streak=N`, `thaw_streak=N`
- `frost_monitor_add.cjs` — создание push-монитора в Uptime Kuma 2.5.3
  (socket.io; push_token Kuma при socket-add НЕ генерирует — задавать
  через sqlite вручную)
- `systemd/weather-frost@.service` + 3 таймера (21:30 / 00:10 / 09:30,
  Europe/Moscow, Persistent=true)

## Методика (калибровка на 14.10.2026, ночи 07→08 / 11→12 / 12→13 / 13→14.10)

| Метод | Формула | Bias |
|---|---|---|
| A (радиационный) | OM Tmin + bias | −2.9 (точки −3.1, −2.7) |
| A2 (облачный) | OM Tmin + bias | −0.6 (точки −0.2, −1.0) |
| B (затухание) | Teq = Td − 2, τ = 2.5 ч, минимум ≈ восход − 2.4 ч | — |

Вердикт = среднее активных методов; поверхность = воздух − 2.5.
Проверка ночи 13→14.10: факт −3.8 @05:05, оценка A+B −3.7…−3.8 (точная).

## Сезонный контур (v1.1.0 — «дача в холодном останове»)

Стабильные морозы делают ночные сводки о заморозках шумом. Контур
переключает поведение дежурного по факту ночей (решает `verify` 09:30):

| Режим | Поведение |
|---|---|
| `garden` (осень) | алерты заморозка: Kuma down + TG в 21:30/00:10, итог утром |
| `winter` (останов) | ночные сводки молчат (Kuma up «зима \| …»); TG только вечерний дайджест, если включён (`--set digest=on`) |

Переходы (гистерезис по факту, счётчики в `frost_state.json`):

- `garden → winter`: 5 ночей подряд факт Tmin ≤ −2°
- `winter → garden`: 5 ночей подряд факт Tmin ≥ 0° И календарь ≥ апреля
  (февральские оттепели режим не переключают; ночь в диапазоне −2…0
  сбрасывает обе серии — лёгкий мороз не весна и не глубокая зима)

Зимние алерты-аномалии (TG + Kuma down):

- Tmin (прогноз или факт) ≤ −25° — аномальный мороз (`DEEP_COLD`)
- промах прогноза ≥ 5° — дрейф калибровки/сбой станции (`MISS_ALERT`),
  работает и в садовом режиме
- станция молчит > 3 ч — поллер/датчик (`STALE_H`, алерт раз в сутки)

Kuma-push идёт каждый проход (21:30/00:10/09:30) — монитор 77 остаётся
пульсом дежурного: если vitele/скрипт умрёт, Kuma поднимет тревогу по
отсутствию push. Вся зима тихо копит `frost_log.csv` — к весне датасет
«прогноз vs факт» для перекалибровки bias.

Защита журнала (v1.1.0): `verify` не пишет строку, пока ночь идёт
(повторные дневные прогоны не портят CSV), и не дублирует строку за
ту же ночь.

## Инфраструктурные зависимости (vitele)

- станция: `/home/auditbot/weather-dash/weather.db` (read-only)
- OM: только через `curl --resolve api.open-meteo.com:443:5.9.98.12`
  (прямой egress на api.open-meteo.com закрыт)
- Telegram: relay `TELEGRAM_API_BASE` из `report.env` (api.telegram.org
  напрямую закрыт)
- Kuma: push-монитор id=77 «Заморозок — ночной дежурный (push)»,
  URL в `frost_push.conf` (600); интервал 10 ч + 1 ретрай 2 ч рассчитан
  на связку пушей 21:30 / 00:10 / 09:30 (макс. разрыв 9.3 ч)

## Артефакты (на VM, рядом со скриптом)

- `frost_state.json` — текущая ночь: методы, сценарий, вердикт;
  сезон (`season`), счётчики серий (`frost_streak`/`thaw_streak`), флаг
  дайджеста (`winter_digest`), метка последнего stale-алерта
- `frost_log.csv` — журнал «прогноз vs факт» (обучение bias по типам ночей;
  зимой — тихий сбор для перекалибровки)
