## TL;DR

Вечером 21.09 обнаружено: HP V1910-24G (.74) перестал отвечать по SNMP
(UDP/161 timeout) и telnet (:23 closed) при живом ping и веб-интерфейсе.
Причину установить не удалось (зависание стека Comware 5.20 при длительном
аптайме — известное поведение модели). Перезагрузка свитча восстановила
работу; часы выставлены (RTC у модели нет — после ребута время слетает),
NTP-сервер 192.168.8.146, SNMP (read-only community), syslog на .146
подтверждены в конфиге и сохранены во flash. После фикса — синхронизация
(stratum 4, референс .146) и ночь без замечаний.

## Хроника (MSK)

1. **21.09 ~22:48** — ревизия мониторинга: сэмплов .74 в dash.db нет, SNMP
   не отвечает (см. 2026-09-21-monitoring-review.md).
2. **23:08** — диагноз с vitele: ping OK (2.3 мс), ARP REACHABLE; tcp/22, 23,
   80 открыты по-разному — фактически SNMP timeout, telnet connect refused,
   web 301 живой. NTP-пробы к кандидатам в LAN (.1, .37, .69, .136,
   10.147.17.1) — молчат; единственный NTP в сети — 192.168.8.146 (chrony).
3. **~23:37** — свитч перезагружен (через веб-интерфейс; вход с капчей,
   автоматизация ограничена).
4. **23:52** — recon: telnet/ssh/web поднялись; uptime 0:24; SNMP всё ещё
   timeout; `screen-length disable` для сессии.
5. **00:01–00:06** — фикс через telnet (scheme-аутентификация):
   `display current-configuration` показал, что NTP/SNMP/loghost **уже были**
   настроены ранее (`ntp-service unicast-server 192.168.8.146`,
   `snmp-agent` + read-only community, `info-center loghost 192.168.8.146`,
   `clock timezone MSK add 03:00:00`). Выполнено: `clock datetime 00:06:20
   09/22/2026` (после ребута часы сброшены), `sysname HP_V1910_24G_JE006A`,
   `save` — конфиг записан в flash:/startup.cfg (проверено
   `display saved-configuration | include …`).
6. **00:07** — верификация: SNMP отвечает (sysUpTime/sysDescr/sysName);
   `display ntp-service status`: synchronized, stratum 4, reference
   192.168.8.146; chrony на vitele видит .74 (20 пакетов, 0 drop).
7. **Ночь 21→22** — чисто: 597 NTP-пакетов от .74, 0 drop; сэмплы в dash.db
   с 00:03 без дыр; netlog HP пишет стабильно.

## Выводы и хвосты

- **Root cause** точно не доказан: модель 2010–2018 гг., Comware 5.20
  Release 1519P06 (EOL), известны деградации при большом аптайме. Аптайм до
  инцидента — длительный (перезагрузок не было с ввода).
- **Урок:** после любого ребута V1910 время сбрасывается — NTP с .146
  подтягивает его автоматически; SNMP-агент после ребута поднимался с
  задержкой (в 23:52 ещё timeout, после 00:06 — стабильно).
- Температурный сенсор .74 в dash.db отдаёт константу 30 °C (623 ночных
  сэмпла tmin=tmax=30) — вероятно фиктивное значение OID; уточнить корректный
  OID температуры Comware при случае (не срочно).
- Мониторинг: Kuma ping-монитор .74 есть; SNMP-сэмплы .74 теперь в dash.db
  наравне с .65/.66/.76/.81.
- При повторении зависания — процедура: перезагрузка через web, далее часы +
  save (документировано здесь).
