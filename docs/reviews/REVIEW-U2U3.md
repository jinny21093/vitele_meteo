## 4. Адаптации U2/U3 (на veto)

| # | Что | Почему |
|---|---|---|
| B-1 | **Конверты hourly/daily содержат `fields`**: `{from, to, fields, rows}` вместо `{from, to, rows}` из ТЗ. | Аддитивно; клиенту не надо знать порядок колонок наизусть, а `load_agg_fields` может законно отдать подмножество списка ТЗ при эволюции схемы (тогда WARN в лог). Единый стиль с /api/history. |
| B-2 | **Heatmap и календарь осадков — HTML-сетки с CSS-классами**, не Chart.js. | У Chart.js 4 нет heatmap без стороннего контроллера (npm-плагин запрещён §0.1/§0.3); inline-стили запрещены §0.6 — палитра вынесена в классы hm-1..hm-7 (значения = colorForTemp), tooltip — атрибут `title`. Календарю сетка нужна всё равно. |
| B-3 | **Дождь на «Сутках»**: столбики = приращения накопительного счётчика типпера `rain_total_mm` по корзинам 15 мин; кумулятив = бегущая сумма. Сброс счётчика (RAIN_COUNTER_RESET) клампится в 0 → сумма за сутки консервативна. | `rain_hour_mm` — rolling-окно, дельты от него шумят и дважды считают стыки часов; счётчик — точный источник, тот же, что использует материализатор этапа B. |
| B-4 | **app.js: +`refreshHeader()`** (шапка §4.0 на U2/U3: /api/now → свежесть, /api/events 24 ч → 🔴 BATTERY_LOW) и +`chartTheme()` (цвета Chart.js из CSS-переменных — легально с тумблером темы). `page-now.js` намеренно НЕ тронут. | §4.0 требует шапку на всех экранах, но page-now заполняет её из своих данных — дублировать его рефакторингом не стал (его код вы принимаете по п.4 ревью). |
| B-5 | **Селектор 7/30/90 хранится в localStorage** (`weather-month-days`). | Мелочь QoL; при veto — одна строка. |
| B-6 | **UI_VERSION 0.1.0 → 0.2.0** (app.js) синхронно с SERVER_VERSION. | semver §4.0: minor = новые экраны. |
