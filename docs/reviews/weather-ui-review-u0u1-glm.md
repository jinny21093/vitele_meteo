## 3\. Находки ревью

### 3.1. 🔴 Семантика окна `/api/events` — дыра в ТЗ (моя ошибка)

В v1.0 был параметр `include_open`; при переписывании §5.5 в v1.1 я его потерял. Следствие: события, начавшиеся раньше окна и всё ещё открытые, **невидимы ни в каком запросе** — а `DRY_SPELL` по определению может быть открыт неделями. Это же корень A-11 (батарея 🔴 не находит событие старше 24 ч).

**Фикс — семантика перекрытия (в U4 + патч §5.5):**

```sql
WHERE (ts_start >= ? AND ts_start <= ?)   OR (ts_start <  ? AND (ts_end IS NULL OR ts_end >= ?))
```

(плейсхолдеры: from, to, from, from). Клиент показывает события с `ts_start < from` как «идёт с более раннего времени». Параметр `include_open` отменён окончательно.

### 3.2. 🟡 Порт-фолбэк 8090 — коллизия

8090 занят weather-api (этап B). Фолбэк меняется на **8091** — патч §12.3.

### 3.3. 🟡 ZeroTier и старт демона

Если ZT-интерфейс поднят позже демона — bind падает, `return 1`, systemd перезапустит через 10 с, цикл до подъёта ZT. Самоисцеляемо, но шумно. В U7-юнит:

```ini
[Unit]After=network-online.target zerotier-one.serviceWants=network-online.target zerotier-one.service
```

### 3.4. 🟢 Ниты (не блокируют)

-   `window_delta` — f-string по внутренней константе допустимо (значение не пользовательское), но для дисциплины §0.7 добавить assert по whitelist.
-   `do_HEAD` отсутствует → 501. ТЗ не требует; опционально.
-   Лог в локальном TZ вместо `Z` из примера §9 — ISO8601-валидно, оставить.
-   `sqlite3.connect(timeout=10)` + следом `PRAGMA busy_timeout=5000` — финальное значение 5000, параметр коннекта просто лишний.

## 4\. Ответы на открытые вопросы агента

1.  **A-5 и A-10** — решены в §2: оба приняты, A-10 вообще не отклонение.
2.  **Стратегия 8090 (два API-стека).** Два read-API над одной БД — двойная поверхность и двойное сопровождение; они неизбежно разъедутся. Рекомендация: **после U7** провести аудит потребителей 8090 (журнал weather-api, Kuma-мониторы, скрипты) и закрыть его либо перевести на localhost. Не раньше U5 — до паритета по `/forecast` он ещё нужен.
3.  **Старт без кред.** Текущее поведение правильное: сервер жив, `/api/health` отвечает (Kuma видит сервис), authed-эндпоинты честно отдают 503, ERROR в journald при старте. Альтернатива — падать в restart-loop — хуже: проблема в одной строке файла.

### §5.1 (замена целиком)

> **GET /api/now**
> 
> Ответ (контракт v1.2.3; таблицы `current` в схеме v2 нет):
> 
> ```json
> {  "now": <epoch>,  "current": { "<колонки weather>: значения" },  "status": {"collector_ok": <bool>, "last_poll_ts": <int>, "gap_s": <int>},  "p_tendency_3h": <float|null>}
> ```
> 
> -   `current` — последняя строка `weather` **плоским словарём** (raw + L1 + L2-short). Вложенная группировка Indoor/Outdoor/… из ранних версий — отменена. Сервер отдаёт все колонки, **кроме** `id` и `schema_version` (явный список, не `SELECT *`).
> -   `p_tendency_3h` — для карточки давления (§4.1): avg(последние 10 мин) − avg(10 мин 3 ч назад), окна по времени, не LAG-строки.
> -   `collector_ok`: `gap_s < 180` (3 цикла коллектора).
> -   Пустая БД → 503 + `{"error": "current is empty, collector has not written yet"}`. UI — плашка «Инициализация…», повтор через 10 с.
> -   p95 < 50 мс.

### §5.5 (дополнения)

> -   **Семантика окна — перекрытие:** попадает событие, начавшееся внутри окна, ЛИБО начавшееся раньше и открытое/закрывшееся после `from`:

> ```sql

>

Фильтр по типу вне каталога → 400.
